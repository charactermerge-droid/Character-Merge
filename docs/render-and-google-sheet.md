# Staging on Render (free), with the Google Sheet as the catalog

```
Google Sheet ──(Sheets API, read-only, as fusion-server@charactermerge-staging)──► Render: charactermerge-server ──HTTPS──► Unity (Staging)
                                                                                    └─ placeholder thumbs/videos from server/local-storage
```

Defined in [`render.yaml`](../render.yaml) at the repo root. Every push to `main` redeploys.

## Pieces and where they live

| Piece | Where | Secret? |
|---|---|---|
| Content sheet "CharacterMerge Content" | charactermerge@gmail.com (private) | no |
| Google Cloud project `charactermerge-staging` | charactermerge@gmail.com | no billing needed: Sheets API + service accounts are free |
| Service account `fusion-server@charactermerge-staging.iam.gserviceaccount.com` | that project | no |
| Its JSON key | `server/google-sa.json` (+ single-line copy `google-sa.min.json`), **gitignored**; and Render env `GOOGLE_SA_JSON` | **yes** |
| `ADMIN_SECRET`, `LOCAL_SIGNING_SECRET` | generated by Render (`generateValue`) | **yes**: read them in the Render dashboard |
| Sheet ID, everything else | `render.yaml` | no |

## One-time setup

1. **Sheet** (done): "CharacterMerge Content", owned by charactermerge@gmail.com, tabs `characters` and `merges`,
   shared with `fusion-server@charactermerge-staging.iam.gserviceaccount.com` as Viewer, General access **Restricted**.
   Edit content there. Anything new must keep the same column order.
2. **Render account:** https://dashboard.render.com/register, easiest with **GitHub** so it can see the repo.
3. **Dashboard → New → Blueprint →** repo `mnTis325/CharacterMerge` → it reads `render.yaml`.
4. When asked for **`GOOGLE_SA_JSON`**, paste the entire contents of `server/google-sa.min.json` (one line).
5. **Apply.** First build takes a few minutes. The service URL looks like `https://charactermerge-server-xxxx.onrender.com`.
6. Check `<url>/health`: it should show `"characters":4,"merges":6`.

## Unity

`Assets/FusionConfig.asset` → **Staging → Server Origin** = the `onrender.com` URL → **Environment** = Staging → Play.

Free instances **sleep after ~15 minutes idle**; the first request then takes ~30-60 s. Open `<url>/health` in a
browser before a demo, or raise `apiTimeout` in the config (the default is 15 s).

## Operating

| Task | How |
|---|---|
| Publish a sheet edit now | `curl -X POST <url>/admin/refresh -H "x-admin-secret: <ADMIN_SECRET from Render>"`, otherwise within 5 min |
| Logs | Render dashboard → the service → Logs |
| Redeploy | push to `main`, or dashboard → Manual Deploy |
| Rotate the Google key | `gcloud iam service-accounts keys create ...` → update `GOOGLE_SA_JSON` in Render → delete the old key with `gcloud iam service-accounts keys delete` |

## Troubleshooting

| Log line | Fix |
|---|---|
| `need tabs named "characters" and "merges" (found: ...)` | rename the tab |
| `Share the sheet with fusion-server@... as Viewer` | step 1 |
| `GOOGLE_SA_JSON is not valid JSON` | re-paste `google-sa.min.json`, the whole line |
| Unity: timeout on the first call | the instance was asleep; retry |

## Local, against the same sheet

`server/.env`: `SHEET_SOURCE=google` (the `GOOGLE_SA_JSON_FILE=./google-sa.json` line is already there), then `npm run sheet` and `npm start`.
